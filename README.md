## Архитектура

Проект разделён на четыре слоя. Зависимости направлены только «внутрь»:
UI зависит от сервисов, сервисы — от домена и абстракции хранилища,
а инфраструктура реализует эту абстракцию.

```
┌──────────────────────────────────────────────────────────┐
│  Presentation (CLI)                                      │
│  cli/main.py · cli/app.py · cli/prompts.py · cli/render.py│
└───────────────────────────┬──────────────────────────────┘
                            │ вызовы use case
┌───────────────────────────▼──────────────────────────────┐
│  Application (services)                                  │
│  services/task_service.py · services/exporter.py         │
└───────────────┬───────────────────────────┬──────────────┘
                │                           │
┌───────────────▼──────────────┐  ┌─────────▼──────────────┐
│  Domain                      │  │  Repository (interface)│
│  models.py · validation.py   │  │  repositories/base.py  │
│  exceptions.py               │  └─────────┬──────────────┘
└──────────────────────────────┘            │ реализация
                                ┌───────────▼──────────────┐
                                │  Infrastructure          │
                                │  json_repository.py      │
                                └──────────────────────────┘
```

### Использованные паттерны и приёмы

| Паттерн / приём | Где применяется | Зачем |
|---|---|---|
| **Repository** | `TaskRepository`, `JsonTaskRepository` | Бизнес-логика не знает, как именно хранятся задачи. Хранилище можно заменить на БД или in-memory fake без изменения сервисов и UI. |
| **Layered Architecture** | `domain` → `services` → `cli` | Чёткое разделение ответственности, код проще читать и тестировать. |
| **Dependency Injection** | `TaskService(repository)`, `TaskManagerApp(service, palette)` | Зависимости передаются снаружи, что позволяет подменять их в тестах. |
| **Strategy (упрощённый)** | `SortField` + `TaskService._sort_key` | Разные стратегии сортировки выбираются через enum, без ветвления в UI. |
| **DTO / сериализация** | `Task.to_dict()` / `Task.from_dict()` | Единая точка преобразования доменной модели в JSON и обратно. |
| **Atomic write** | `JsonTaskRepository.save()` | Запись во временный файл + `os.replace`, чтобы сбой не разрушил данные. |

### Слои подробнее

1. **Domain (`src/task_manager/domain/`)** — не зависит ни от чего, кроме
   стандартной библиотеки.
   - `models.py` — `Task`, `Priority`, сериализация.
   - `validation.py` — правила проверки названия, описания, даты и
     приоритета.
   - `exceptions.py` — `ValidationError`, `StorageError`,
     `TaskNotFoundError`.
2. **Application (`src/task_manager/services/`)** — сценарии использования.
   - `TaskService` — добавление, выполнение, удаление, фильтрация,
     сортировка, поиск, статистика.
   - `exporter.py` — экспорт в CSV/TXT.
3. **Infrastructure (`src/task_manager/repositories/`)** — работа с файлом.
   - `base.py` — абстрактный интерфейс и `LoadResult`.
   - `json_repository.py` — атомарное чтение/запись JSON, восстановление
     после повреждения.
4. **Presentation (`src/task_manager/cli/`)** — консольный интерфейс.
   - `main.py` — разбор аргументов командной строки и запуск.
   - `app.py` — меню и обработчики действий.
   - `prompts.py` — ввод с валидацией и подтверждениями.
   - `render.py` — таблица задач с цветами.
   - `colors.py` — ANSI-цвета и `colorama`.

## Установка и запуск

### Требования

- Python **3.14+** (проект создан на 3.14.4).
- [`uv`](https://docs.astral.sh/uv/) 0.13+.

### Установка зависимостей

```bash
git clone <url-репозитория>
cd task-manager
uv sync
```

`uv sync` создаст `.venv`, установит `colorama` и dev-зависимости
(`pytest`, `ruff`), а также установит сам пакет в editable-режиме.

### Запуск

```bash
# через entry point
uv run task-manager

# как модуль
uv run python -m task_manager

# с собственным файлом данных
uv run task-manager --data-file ./my_tasks.json

# путь можно задать переменной окружения
TASK_MANAGER_FILE=~/tasks.json uv run task-manager

# без цветов (например, для логов)
uv run task-manager --no-color
```

Доступные параметры:

| Параметр | Описание |
|---|---|
| `-f`, `--data-file PATH` | Путь к JSON-файлу с задачами. По умолчанию `tasks.json` в текущем каталоге. |
| `--no-color` | Отключить ANSI-цвета. |
| `--version` | Показать версию программы. |
| `-h`, `--help` | Справка. |

## Использование

После запуска отображается шапка со статистикой и меню:

```
=== Менеджер задач ===
Файл данных: /home/user/task-manager/tasks.json
Всего задач: 3 | активных: 2 | выполненных: 1 | просрочено: 0

----------------------------------------------
  1. Добавить задачу
  2. Показать задачи
  3. Отметить задачу выполненной
  4. Удалить задачу
  5. Найти задачи
  6. Экспортировать задачи
  0. Выход
----------------------------------------------
Выберите пункт:
```

### Добавление задачи

Пункт `1`. Программа последовательно спрашивает:

```
Название: Купить молоко
Описание (необязательно): Два литра, 2.5%
Срок выполнения (ДД.ММ.ГГГГ): 05.11.2026
Приоритет (1 — высокий, 2 — средний, 3 — низкий) [2]: 1
✔ Задача №1 «Купить молоко» добавлена. Срок: 05.11.2026, приоритет: высокий.
```

При ошибке ввода выводится понятное сообщение, и вопрос повторяется —
программа не завершается и не «падает».

### Просмотр, фильтрация и сортировка

Пункт `2`. Сначала выбирается фильтр, затем сортировка:

```
Что показать (1 — все, 2 — только активные, 3 — только выполненные) [1]:
Сортировка (1 — по сроку, 2 — по приоритету, 3 — по статусу) [1]:

Задачи (все, по сроку):
№  Статус   Срок        Приоритет  Название
-  -------  ----------  ---------  --------------
1  активна  03.11.2026  низкий     Позвонить маме
2  активна  05.11.2026  высокий    Купить молоко
3  активна  15.11.2026  средний    Сдать отчёт
```

- Номера в таблице всегда начинаются с `1` и относятся к текущему
  отфильтрованному списку.
- Просроченный срок выделяется **красным**, срок «сегодня» — жёлтым.
- Выполненные задачи отображаются приглушённым цветом.

### Отметка выполнения

Пункт `3`. Показываются только активные задачи, нужно ввести их номер:

```
Номер задачи для выполнения (0 — отмена): 2
✔ Задача «Купить молоко» отмечена как выполненная.
```

Ввод `0` или пустой строки отменяет действие.

### Удаление с подтверждением

Пункт `4`. Показываются все задачи, затем запрашивается подтверждение:

```
Номер задачи для удаления (0 — отмена): 1
Удалить задачу «Позвонить маме» безвозвратно? [нет]: да
✔ Задача «Позвонить маме» удалена.
```

По умолчанию выбран ответ «нет». Принимаются `да/д/yes/y/1` и
`нет/н/no/n/0`. Любой другой ответ приводит к повторному вопросу.

### Поиск

Пункт `5`. Ищет подстроку без учёта регистра в названии **и** описании:

```
Ключевое слово в названии или описании: молоко
```

### Экспорт

Пункт `6`. Можно выбрать CSV или TXT и путь к файлу. Если расширение не
указано, оно добавляется автоматически.

```
Формат файла (1 — CSV, 2 — TXT) [1]: 1
Путь к файлу [tasks_export_20261103-113121.csv]:
✔ Экспортировано задач: 3. Файл: /home/user/task-manager/tasks_export_20261103-113121.csv.
```

### Отмена и выход

- `0` в главном меню — корректный выход.
- `0` или пустая строка при выборе номера задачи — отмена действия.
- `Ctrl+C` / `Ctrl+D` — корректное завершение без traceback.

## Формат хранения данных

Задачи хранятся в `tasks.json` (путь настраивается). Пример:

```json
{
  "version": 1,
  "saved_at": "2026-11-03T11:31:21",
  "tasks": [
    {
      "id": 1,
      "title": "Купить молоко",
      "description": "Два литра, 2.5%",
      "due_date": "2026-11-05",
      "priority": "high",
      "completed": true,
      "created_at": "2026-11-03T11:31:21"
    }
  ]
}
```

| Поле | Тип | Описание |
|---|---|---|
| `version` | int | Версия схемы (сейчас `1`). |
| `saved_at` | string | Время последнего сохранения (ISO 8601). |
| `tasks` | array | Список задач. |
| `id` | int | Уникальный идентификатор задачи. |
| `title` | string | Название. |
| `description` | string | Описание (может быть пустым). |
| `due_date` | string | Срок в формате `YYYY-MM-DD` (ISO 8601). |
| `priority` | string | `high`, `medium` или `low`. |
| `completed` | bool | Статус выполнения. |
| `created_at` | string | Дата создания (ISO 8601). |

**Почему ISO, а не `ДД.ММ.ГГГГ`?** ISO-даты однозначны, корректно
сортируются как строки и не зависят от локали. Пользователь при этом всегда
видит привычный формат `ДД.ММ.ГГГГ`.

Сохранение выполняется **после каждого изменения** (добавление,
выполнение, удаление). Запись атомарная: данные пишутся в
`tasks.json.tmp`, затем `os.replace` подменяет основной файл. Если запись
не удалась, изменение откатывается и в памяти, и на диске.

## Валидация ввода

| Поле / действие | Правила | Поведение при ошибке |
|---|---|---|
| Название | Не пустое; пробелы по краям удаляются, внутренние схлопываются; ≤ 200 символов | Сообщение и повторный ввод |
| Описание | Необязательное; ≤ 2000 символов | Сообщение и повторный ввод |
| Срок | Строго `ДД.ММ.ГГГГ` (2 цифры + 2 цифры + 4 цифры); существующая дата; не раньше сегодняшнего дня | Сообщение с примером и повторный ввод |
| Приоритет | `1`/`2`/`3` или `высокий`/`средний`/`низкий`; по умолчанию `2` | Сообщение и повторный ввод |
| Фильтр / сортировка | Только предложенные пункты | Сообщение и повторный ввод |
| Номер задачи | Целое в диапазоне `1..N`; `0` — отмена | Сообщение и повторный ввод |
| Подтверждение удаления | `да/д/yes/y/1` или `нет/н/no/n/0`; пусто = «нет» | Сообщение и повторный ввод |
| Поиск | Непустая строка | Сообщение, возврат в меню |

Пример диалога при неверной дате:

```
Срок выполнения (ДД.ММ.ГГГГ): 31.02.2026
  ✖ Дата «31.02.2026» не существует. Проверьте день и месяц.
Срок выполнения (ДД.ММ.ГГГГ): 2026-12-31
  ✖ Дата «2026-12-31» не соответствует формату ДД.ММ.ГГГГ. Пример: 31.12.2026.
Срок выполнения (ДД.ММ.ГГГГ): 31.12.2026
```

## Сортировка и фильтрация

| Сортировка | Порядок | Дополнительные ключи |
|---|---|---|
| По сроку | Ближайшие сверху | Приоритет (высокий → низкий), затем `id` |
| По приоритету | Высокий → средний → низкий | Срок, затем `id` |
| По статусу | Активные перед выполненными | Приоритет, срок, `id` |

Фильтры: **все**, **только активные**, **только выполненные**.
Сортировка и фильтрация реализованы в `TaskService` и не зависят от
консольного интерфейса.

## Обработка ошибок

| Ситуация | Поведение программы |
|---|---|
| `tasks.json` отсутствует | Запуск с пустым списком, без ошибки. |
| Файл пустой | Предупреждение, пустой список. |
| JSON повреждён | Файл копируется в `tasks.json.corrupt-<дата>-<время>`, создаётся новый пустой валидный файл, выводится предупреждение. |
| Неожиданная структура JSON | То же: резервная копия + пустой список. |
| Одна запись повреждена | Запись пропускается с предупреждением, остальные загружаются. |
| Повторяющийся `id` | Дубликат пропускается с предупреждением. |
| Нет прав на чтение | Понятное сообщение, код возврата `1`. |
| Нет прав на запись | Операция не применяется (откат), сообщение, программа продолжает работу. |
| Диск переполнен / ошибка ОС | `StorageError` с описанием, состояние не меняется. |
| Неверный ввод | Сообщение и повторный запрос. |
| Неверная кодировка ввода (`UnicodeDecodeError`) | Ввод читается как байты и декодируется с fallback: UTF-8 → CP1251 → KOI8-R → CP866. При полной неудаче — понятное сообщение и возврат в меню, без traceback. |
| `Ctrl+C` / `Ctrl+D` | Корректный выход без traceback. |

Все ожидаемые исключения наследуются от `TaskManagerError` и
обрабатываются в одном месте — в цикле меню. Пользователь никогда не видит
стек вызовов.

### Проблема с кодировкой терминала (`UnicodeDecodeError`)

Если терминал или IDE-консоль отправляет кириллицу не в UTF-8 (либо
многобайтовый символ приходит частями), обычный `input()` может упасть с
`UnicodeDecodeError`. В проекте это обработано на двух уровнях:

1. Ввод читается из `sys.stdin.buffer` как байты, а затем декодируется с
   перебором кодировок: текущая кодировка stdin, UTF-8, CP1251, KOI8-R,
   CP866. Поэтому текст в типичных русских кодировках вводится корректно.
2. Вывод (stdout/stderr) переконфигурируется с `errors="replace"`, чтобы
   сообщение программы не упало из-за неподдерживаемого символа.

Если символы всё равно отображаются как `?` или `�`, настройте локаль и
перезапустите программу:

```bash
export LANG=C.UTF-8
export LC_ALL=C.UTF-8
uv run task-manager
```

Или включите UTF-8-режим Python принудительно:

```bash
PYTHONUTF8=1 uv run task-manager
```

Проверить текущую локаль можно командой `locale`. Рекомендуется значение,
содержащее `UTF-8` (например, `ru_RU.UTF-8` или `C.UTF-8`).

## Экспорт

- **CSV**: разделитель `;`, кодировка `utf-8-sig` (корректно открывается в
  русском Excel), заголовки и все поля задачи.
- **TXT**: заголовок, статистика, таблица задач и список описаний.

Экспортируются все задачи независимо от текущего фильтра. Ошибки записи
(нет прав, неверный путь) обрабатываются и не приводят к падению.

## Цветной вывод

Используется библиотека `colorama` (для корректной работы на Windows) и
ANSI-коды:

- 🔴 просроченный срок;
- 🟡 срок «сегодня»;
- 🟢 выполненные задачи;
- приоритет: высокий — красный, средний — жёлтый, низкий — зелёный.

Цвета автоматически отключаются, если вывод перенаправлен в файл, а также
при `--no-color` или переменной окружения `NO_COLOR`.

## Использование ИИ-инструмента

При разработке использовался ИИ-ассистент **OpenCode** (модель Big Pickle).
ИИ применялся для генерации:

1. строгой проверки даты `ДД.ММ.ГГГГ` и сравнения с текущей датой;
2. обработки ошибок чтения/записи JSON (отсутствие файла, повреждённые
   данные, права доступа);
3. подтверждения удаления задачи;
4. вспомогательного кода таблицы и повторного ввода;
5. устойчивого чтения ввода при неверной кодировке терминала
   (`UnicodeDecodeError`).

Сгенерированный код был **проверен вручную**, дополнен и покрыт тестами.
Подробные запросы, ответы, фрагменты кода и замечания по ревью находятся в

## Ограничения и идеи для развития

- Однопользовательский режим: нет блокировок при одновременном запуске
  нескольких экземпляров.
- Нет повторяющихся задач и напоминаний.
- Нет редактирования задачи (только добавление, выполнение, удаление).
- Возможные улучшения:
  - редактирование полей задачи;
  - дедлайны с временем и напоминания;
  - теги и категории;
  - хранение в SQLite через новую реализацию `TaskRepository`;
  - экспорт в ICS/JSON;
  - TUI на `textual` или веб-интерфейс на `FastAPI`.
